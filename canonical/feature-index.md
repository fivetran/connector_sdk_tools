# Connector SDK Feature Index

Discovery index for Connector SDK features. Use it to notice when a user's need matches a feature, then mention the feature and link its docs.

Rules:
- If the user's need matches a row's **Suggest when**, mention the feature in one sentence and link the docs. Do not wait for the user to ask.
- Before using a feature in code, read its detailed section in `sdk-reference.md` (if one exists) and the docs page.
- Adding a feature: add one row here. Keep rows to one sentence per cell.

| Feature | What it does | Suggest when | Docs link | Example |
|---------|--------------|--------------|-----------|---------|
| Record-and-replay regression testing (Public Preview) | `@action` records source reads with `fivetran debug --record` and replays them with `--replay` to catch regressions without calling the live API. | User changes connector code, wants regression tests, or asks how to verify a fix did not break existing behavior. | [Regression testing](https://fivetran.com/docs/connector-sdk/testing/regression-testing) | [Regression test](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/quickstart/regression_test) |
| Deferred truncate | `op.truncate(table, deferred=True)` deletes table data only after `update()` returns successfully, so a failed sync removes nothing. | Connector does a full refresh that replaces a table, and a failed sync must not leave the table empty. | [Deferred truncate](https://fivetran.com/docs/connector-sdk/technical-reference/connector-sdk-operations#deferredtruncate) | [Deferred truncate operation](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/common_patterns/truncate_operation/deferred_truncate_operation) |
| Multiple schemas | Lets one connector sync tables from several source schemas into the destination. Each table gets a `schema` key in `schema()`, and each record operation passes a matching `schema=`. | Source has several logical schemas or databases to sync into separate destination schemas. | [Declaring multiple schemas](https://fivetran.com/docs/connector-sdk/building-connectors/connector-sdk-concepts/schema-management#declaringmultipleschemas) | [Multiple schema](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/quickstart/multiple_schema) |
| Stateless CLI and options file | Sets deploy settings from flags, env vars, or a file, instead of copying them from the existing connection. The order is flags, env vars, options file, `pyproject.toml`, then SDK defaults. `pyproject.toml` only covers the Python version and proxy host key, and is ignored with `--package-id`. Available from SDK 3.0.0. | User is deploying a connector, or a redeploy fails with `--python-version is required`. | [Options file](https://fivetran.com/docs/connector-sdk/technical-reference/options-file) | - |
| Unstructured file uploads (Private Preview) | Lets a connector upload unstructured files (documents, PDFs, and similar) to the destination. | Source delivers raw files or documents rather than rows. | [File uploads](https://fivetran.com/docs/connector-sdk/technical-reference/connector-sdk-file-uploads) | [Unstructured data](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/quickstart/unstructured_data) |
| Proxy agent (Beta) | Routes connector traffic through a proxy agent so the connector can reach private or on-premises sources. | Source is only reachable from a private network. | [Proxy agent](https://fivetran.com/docs/connector-sdk/building-connectors/connection-options/proxy-agent) | [Proxy agent](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/common_patterns/proxy_agent) |
| Setup form (`configuration_form`, Beta) | Defines a configuration UI form in the connector so users enter settings in Fivetran instead of editing `configuration.json`. | Connector needs user-entered settings, or the user asks for a setup UI. | [Setup form](https://fivetran.com/docs/connector-sdk/technical-reference/connector-sdk-setup-form) | [Configuration form](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/quickstart/configuration_form) |
| Custom database drivers (Private Preview, hidden) | Lets a connector import and use an external database driver. | Do not suggest. Only discuss if the user asks for it by name. | [Custom database drivers](https://fivetran.com/docs/connector-sdk/building-connectors/custom-database-drivers) | [Importing external drivers](https://github.com/fivetran/fivetran_connector_sdk/tree/main/examples/common_patterns/importing_external_drivers) |
| Reusable connector packages (Private Preview) | Lets one connector package be reused across multiple connections. | Several connections need the same connector code with different configuration. | [Managing connector packages](https://fivetran.com/docs/connector-sdk/deploying-connectors/managing-connector-packages) | - |
